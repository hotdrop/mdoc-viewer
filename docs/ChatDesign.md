# 実装依頼: Chat形式の質問機能を追加する

## 目的
社内ドキュメント閲覧Webアプリに、Chat形式でドキュメント内容へ質問できる機能を追加してください。
この機能は、GCS上のMarkdown形式ドキュメントを対象としたRAG質問機能のUIです。
ただし、現時点ではRAG Core APIは未完成のため、API連携部分はダミー実装で構いません。

## 前提
- Webアプリは Next.js App Router + TypeScript で実装されています。
- 認証は Firebase Authentication を利用しています。
- 既存アプリの設計・ディレクトリ構成・UIコンポーネント・スタイル規約を優先してください。
- 新規ライブラリ追加は原則避けてください。
- 既存の実装規約に反する独自構成を作らないでください。

## 追加する機能
ドキュメント閲覧アプリ内に、専用のChatページを追加してください。
ページの配置場所やメニューへの追加方法は、既存アプリのルーティング・ナビゲーション構成を確認して、最も自然な形で実装してください。

## Chat機能の目的
このChatは「ドキュメントを探す」機能ではなく、「ドキュメント内容について質問する」機能です。
回答の根拠として参照元ドキュメント一覧を表示し、ユーザーが一次情報を確認できるようにしてください。

## UI要件
ChatGPT風のシンプルなUIにしてください。最低限、以下を実装してください。

- メッセージ一覧
- ユーザー入力欄
- 送信ボタン
- ローディング表示
- ユーザーメッセージ表示
- AI回答メッセージ表示
- 参照元ドキュメント一覧表示

ユーザーメッセージは右寄せ、AI回答は左寄せを基本にしてください。空文字または空白のみの場合は送信ボタンを押せないようにしてください。長文入力の制限は不要です。
回答取得中は、入力欄と送信ボタンを無効化してください。

## 会話履歴
会話履歴は画面メモリ上だけで保持してください。
以下は実装しないでください。

- DB保存
- LocalStorage保存
- SessionStorage保存
- リロード後の復元

画面リロードやページ離脱で履歴が消えて問題ありません。

## API構成
ブラウザからRAG Coreを直接呼び出さないでください。必ず Next.js の Route Handler を経由してください。構成は以下です。

```text
Browser
  -> Next.js Route Handler
  -> 将来の RAG Core API
```

今回は将来のRAG Core APIは呼び出さず、Route Handler内でダミーレスポンスを返してください。

## 追加するAPI
`POST /api/chat` を追加してください。

### Request
```json
{
  "message": "質問本文"
}
```

### Response
```json
{
  "answer": "回答本文",
  "references": [
    {
      "title": "参照元ドキュメントタイトル",
      "url": "/documents/example"
    }
  ]
}
```

## ダミーレスポンス仕様
初期実装では、質問内容に関係なく固定レスポンスを返して構いません。

例:

```json
{
  "answer": "これはダミー回答です。将来的にはRAG Core APIから取得した回答を表示します。",
  "references": [
    {
      "title": "サンプル仕様書",
      "url": "/documents/sample"
    }
  ]
}
```

ただし、将来RAG Core APIへ差し替えやすいように、型定義や関数分割を行ってください。

## 型定義
最低限、以下に相当する型を定義してください。

```ts
type ChatMessage = {
  id: string
  role: 'user' | 'assistant'
  content: string
  references?: ChatReference[]
}

type ChatReference = {
  title: string
  url: string
}

type ChatRequest = {
  message: string
}

type ChatResponse = {
  answer: string
  references: ChatReference[]
}
```

既存プロジェクトに型定義の置き場所や命名規約がある場合は、それに従ってください。

## エラーハンドリング

`/api/chat` の呼び出しに失敗した場合は、Chat上に以下のようなエラーメッセージを表示してください。

```text
回答の取得に失敗しました。時間をおいて再度お試しください。
```

エラー時も画面全体を壊さず、次の質問を送信できる状態に戻してください。

## 参照元ドキュメント表示

AI回答に `references` がある場合は、回答本文の下に参照元ドキュメント一覧を表示してください。各参照元はリンクとして表示してください。表示項目は最低限以下です。

* title
* urlへのリンク

リンクの開き方は既存アプリのドキュメント閲覧導線に合わせてください。

## 実装方針

以下のような責務分離を推奨します。

* Chatページ
* メッセージ一覧コンポーネント
* メッセージアイテムコンポーネント
* 入力フォームコンポーネント
* 参照元一覧コンポーネント
* `/api/chat` Route Handler
* Chat API呼び出し関数
* Chat関連型定義

ただし、既存プロジェクトの構成がある場合はそちらを優先してください。

## やらないこと
今回の実装では以下は不要です。

* RAG Core APIとの本接続
* ストリーミング回答
* 会話履歴の永続化
* フィードバックボタン
* 添付ファイル
* Markdownエディタ
* ドキュメント編集
* 外部共有
* 権限ごとの検索範囲制御
* 複雑なAgent機能

## 完了条件
以下を満たしたら完了です。

* Chat専用ページが表示できる
* 質問を入力して送信できる
* 空入力では送信できない
* 送信後、ユーザーメッセージが表示される
* ダミーAPIからAI回答が返る
* AI回答が画面に表示される
* 参照元ドキュメント一覧がリンクとして表示される
* API失敗時にエラーメッセージが表示される
* 会話履歴はリロードで消える
* 既存のlint/typecheck/buildが通る
* 不要な新規ライブラリを追加していない

## 実装後に確認してほしいこと
実装後、以下を確認してください。

* 既存の設計・命名・ディレクトリ構成に沿っているか
* Chat UIが既存アプリの見た目から大きく浮いていないか
* RAG Core API差し替え時に変更箇所が局所化されているか
* BrowserからRAG Coreを直接呼ぶ設計になっていないか
* 認証済みユーザー向けの既存ページ構成と矛盾していないか

## 最後に
実装前に既存コードベースを調査し、既存のページ構成・UIコンポーネント・API Routeの書き方・認証処理に合わせてから実装してください。
